## Отчёт

Отчёт лежит в `report/main.typ` и собирается на шаблоне
`template/arxiv.typ` (по мотивам пакета arkheion): титульник по образцу
кафедры не тронут, тело свёрстано как препринт arXiv — Computer Modern,
шапка «линии—заголовок», цель работы как аннотация. Старый СТП-стиль
остался в `template/oaip.typ`: вернуть его — замена одного импорта.
Листинги в отчёт читаются напрямую из `1/main.c`..`3/main.c`,
поэтому код в PDF всегда совпадает с тем, что компилируется. Скриншоты
запуска — `report/assets/term_task*.png`, их генерирует `report/make_screens.py`
из реальных запусков: если вывод начался не с ожидаемого приглашения,
генерация падает, чтобы скриншоты не врали. Блок-схемы gostpadi складывает
рядом — `report/assets/1-main.svg` и дальше.

## Задача 1

**Население города ежегодно увеличивается на 1/n наличного состава жителей,
где n — натуральное число. Через сколько лет население города утроится?**

### Решение

```c
#include <stdio.h>
#include <math.h>

//Задача 1. Вариант 5
//Население города ежегодно увеличивается на 1/n наличного состава жителей,
//где n - натуральное число. Через сколько лет население города утроится?

int main(void) {
    float n;
    unsigned int y;

    y = 0;

    printf("Введите коэффициент: ");
    if (scanf("%f", &n) != 1 || n > 0){
        while (pow((1 + 1/n), y) < 3){
            y++;
        }
        printf("\nТребуется %u лет\n", y);
    } else {
        printf("Ошибка\n");
    }

    return 0;
}
```

Разберём, что тут происходит.

За год население становится равно самому себе плюс 1/n от него, то есть
умножается на

```c
1 + 1/n
```

Через y лет его умножили на этот множитель y раз, значит, население выросло
в (1 + 1/n)^y раз. Утроение — это когда степень дотянула до трёх. Отсюда и
цикл:

```c
while (pow((1 + 1/n), y) < 3){
    y++;
}
```

Пока степень меньше трёх, счётчик лет растёт. Как только условие сломалось —
в y лежит первый год, когда население утроилось. Это первый в лабе цикл
**while**: в отличие от for он не знает заранее, сколько итераций понадобится,
и живёт только условием. Степень считает **pow** из math.h — та самая
библиотека, из-за которой в сборке стоит `-lm`.

n объявлен как float, потому что 1/n — дробное число: при n = 2 множитель
1.5, и утроение наступает на третьем году (1.5 → 2.25 → 3.375).

Проверка ввода тут зеркальна первой лабе: в if стоит условие «ввод хороший» —
scanf прочитал число и оно положительное, — и только тогда запускается цикл.
Всё остальное уходит в else с сообщением об ошибке: при n ≤ 0 множитель
перестаёт расти, и цикл не остановился бы никогда.

## Задача 2

**Вычислить число Пи по формуле Грегори, взяв 500 членов ряда:
П/4 = 1 − 1/3 + 1/5 − 1/7 + …**

### Решение

```c
#include <stdio.h>

//Задача 2. Вариант 5
//Вычислить число Пи по формуле Грегори, взяв 500 членов ряда:
//П/4 = 1 - 1/3 + 1/5 - 1/7 + ...

int main(void) {
    double sum = 0;
    double denominator = 1;
    double sign = 1;

    for (int i = 0; i < 500; i++){
        sum = sum + sign / denominator;

        denominator = denominator + 2;
        sign = sign * (-1);
    }

    double pi = sum * 4;

    printf("Число Пи равно: %lf", pi);

    return 0;
}
```

Ряд Грегори — бесконечная сумма, а компьютер бесконечность не прожуёт,
поэтому считается конечный кусок: первые 500 слагаемых. За это отвечает
знакомый по лабам **for**:

```c
for (int i = 0; i < 500; i++){
```

Слагаемые устроены хитро: числитель всё время меняет знак, а знаменатель
бежит по нечётным числам 1, 3, 5, 7… Обе уловки спрятаны в двух строчках
после суммы:

```c
sign = sign * (-1);
```

Умножение на минус единицу каждый шаг переворачивает знак: 1, −1, 1, −1…
Это стандартный приём для знакочередующихся рядов — без ветвления с if.

```c
denominator = denominator + 2;
```

А так получаются нечётные знаменатели: стартуем с 1 и каждый раз делаем
шаг в два.

После цикла в sum лежит частичная сумма, которая по формуле равна П/4 —
умножаем на 4 и печатаем. Все переменные здесь **double**: и слагаемые
дробные, и произведение быстро вырастает по точности.

Кстати, обратите внимание на результат: 3.139593. Два знака после запятой
верные — 3.14, а дальше ряд ещё не доехал. Формула Грегори славится тем,
что сходится до обидного медленно: точность растёт примерно на один знак
на каждые десять раз больше слагаемых. Это не баг программы, а честная
цена этого ряда.

## Задача 3

**Даны целые положительные числа A и B. Найти их наибольший общий делитель
(НОД), используя алгоритм Евклида.**

### Решение

```c
#include <stdio.h>

//Задача 3. Вариант 5
//Даны целые положительные числа A и B. Найти их наибольший общий
//делитель (НОД), используя алгоритм Евклида.

int main(void) {
    unsigned int a, b, c;

    printf("Введите числа a и b: ");

    if (scanf("%u %u", &a, &b) == 2 && a > 0 && b > 0){
        while (b != 0){
            c = a % b;
            a = b;
            b = c;
        }
        printf("НОД: %u\n", a);
    } else {
        printf("Ошибка\n");
    }

    return 0;
}
```

НОД — наибольшее из чисел, на которые делятся и a, и b без остатка.
Перебирать все делители подряд можно, но скучно; Евклид в «Началах» ещё
за триста лет до нашей эры заметил вещество покороче: если d делит и a,
и b, то оно делит и остаток a % b — ведь остаток получается вычитанием
целого числа b из a. Значит,

```c
НОД(a, b) = НОД(b, a % b)
```

и пару можно заменять, пока остаток не станет нулём. Цикл читается прямо
по этой формуле:

```c
while (b != 0){
    c = a % b;
    a = b;
    b = c;
}
```

Временная **c** обязательна: остаток надо спрятать до того, как b перезапишет
a, иначе он потеряется. Прогоним на 48 и 36: (48, 36) → (36, 12) → (12, 0).
b обнулился — в a остался ответ: 12.

Проверка ввода здесь с логическим **&&** из первой лабы: scanf должен
прочитать ровно два числа, и оба строго положительные — НОД нуля с числом
формально равен самому числу, но по условию задачи такого ввода не бывает.
Тип **unsigned int** взят не для красоты: отрицательных чисел в задаче нет,
зато беззнаковый тип вдвое расширяет потолок положительных.
