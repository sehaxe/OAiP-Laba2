## Отчёт

Отчёт лежит в `report/main.typ` и собирается на шаблоне
`template/arxiv.typ` (по мотивам пакета arkheion): титульник по образцу
кафедры не тронут, тело свёрстано как препринт arXiv — Computer Modern,
шапка «линии—заголовок», цель работы как аннотация. Старый СТП-стиль
остался в `template/oaip.typ`: вернуть его — замена одного импорта.
Листинги в отчёт читаются напрямую из `1/main.c`..`3/main.c`,
поэтому код в PDF всегда совпадает с тем, что компилируется. Результаты
запуска — `report/assets/term.json`, его пишет `report/make_screens.py`,
прогоняя настоящие бинарники: если вывод начался не с ожидаемого
приглашения, генерация падает, чтобы рисунки не врали. Терминальные окна
рисуются из JSON вектором прямо в PDF (функция `terminal()` шаблона) —
текст на рисунке выбирается и не мылится. Блок-схемы gostpadi складывает
рядом — `report/assets/1-main.svg` и дальше.

## Блок-схемы

Все схемы отчёта рисует [gostpadi](https://github.com/sehaxe/gostpadi)
напрямую из `main.c`: сам находит ввод-вывод, условия и циклы. Пачка для
отчёта идёт с флагом `--no-split`: схема целиком на одном листе, без
разрывов и соединителей-«кружков», а в А4 её вписывает общий масштаб
пачки — блоки во всех схемах отчёта одного размера, и каждая схема
занимает в отчёте одну страницу. Выход — векторный SVG, в PDF не мылится
ни при каком масштабе.

```bash
gostpadi 1/main.c -o scheme.svg   # одна схема
make schemes                      # перегенерить все три
```

## Задача 1

**Население города ежегодно увеличивается на 1/n наличного состава жителей,
где n — натуральное число. Через сколько лет население города утроится?**

### Решение

```c
#include <stdio.h>

//Задача 1. Вариант 5
//Население города ежегодно увеличивается на 1/n наличного состава жителей,
//где n - натуральное число. Через сколько лет население города утроится?

#define TARGET 3 //во сколько раз должно вырасти население

int main(void) {
    float n;
    unsigned int y;
    double population;
    int c;
    int ok = 0;

    while (!ok) {
        printf("Введите коэффициент: ");
        ok = (scanf("%f", &n) == 1) && (n > 0);

        if (!ok){
            while ((c = getchar()) != '\n' && c != EOF); //вычерпать плохой ввод
            printf("Ошибка: нужно положительное число. Повторите ввод.\n");
        }
    }

    y = 0;
    population = 1;

    while (population < TARGET){
        population = population * (1 + 1/n); //за год население умножается на (1 + 1/n)
        y++;
    }

    printf("Требуется %u лет\n", y);

    return 0;
}
```

Разберём, что тут происходит.

За год население становится равно самому себе плюс 1/n от него, то есть
умножается на

```c
1 + 1/n
```

Через y лет его умножили на этот множитель y раз, значит, население выросло
в (1 + 1/n)^y раз. Утроение — это когда множитель дотянул до трёх. Степень
считать не обязательно: если хранить текущее население и каждый год умножать
его на (1 + 1/n), эффект будет тот же. Отсюда и цикл:

```c
while (population < TARGET){
    population = population * (1 + 1/n);
    y++;
}
```

Пока население меньше цели TARGET, счётчик лет растёт. Как только условие
сломалось — в y лежит первый год, когда население утроилось. Тройка спрятана
в константу TARGET: требование лабы запрещает «голые» цифры в вычислениях.
Это первый в лабе цикл **while**: в отличие от for он не знает заранее,
сколько итераций понадобится, и живёт только условием. Библиотечная степень
здесь не нужна и по правилам: math.h в лабе разрешён только для корней и
тригонометрии, возведение в степень положено писать самому — умножение
в цикле и есть эта самописная конструкция.

n объявлен как float, потому что 1/n — дробное число: при n = 2 множитель
1.5, и утроение наступает на третьем году (1.5 → 2.25 → 3.375).

Проверка ввода живёт в цикле **while** с флагом **ok**: флаг заранее сброшен
в ноль, поэтому тело выполнится как минимум один раз. Ввод хороший, если
scanf прочитал число и оно положительное, — итог проверки запоминается во
флаге; при провале буфер вычерпывается до конца строки и ввод запрашивается
снова. Цикл продолжается, пока ok ложен, поэтому после цикла n заведомо
корректен. Положительность не прихоть: при n ≤ 0 множитель перестаёт
расти, и цикл лет не остановился бы никогда.

## Задача 2

**Вычислить число Пи по формуле Грегори, взяв 500 членов ряда:
П/4 = 1 − 1/3 + 1/5 − 1/7 + …**

### Решение

```c
#include <stdio.h>

//Задача 2. Вариант 5
//Вычислить число Пи по формуле Грегори, взяв 500 членов ряда:
//П/4 = 1 - 1/3 + 1/5 - 1/7 + ...

#define TERMS 500  //сколько членов ряда суммируем
#define STEP 2     //шаг знаменателя: нечётные числа 1, 3, 5, ...
#define FACTOR 4   //частичная сумма равна П/4, значит Пи = сумма * 4

int main(void) {
    double sum = 0;
    double denominator = 1;
    double sign = 1;

    for (int i = 0; i < TERMS; i++){
        sum = sum + sign / denominator;

        denominator = denominator + STEP;
        sign = sign * (-1);
    }

    double pi = sum * FACTOR;

    printf("Число Пи равно: %f\n", pi);

    return 0;
}
```

Ряд Грегори — бесконечная сумма, а компьютер бесконечность не прожуёт,
поэтому считается конечный кусок: первые 500 слагаемых. За это отвечает
знакомый по лабам **for**:

```c
for (int i = 0; i < TERMS; i++){
```

Слагаемые устроены хитро: числитель всё время меняет знак, а знаменатель
бежит по нечётным числам 1, 3, 5, 7… Обе уловки спрятаны в двух строчках
после суммы:

```c
sign = sign * (-1);
```

Умножение на минус единицу каждый шаг переворачивает знак: 1, −1, 1, −1…
Это стандартный приём для знакочередующихся рядов — без ветвления с if.

```c
denominator = denominator + STEP;
```

А так получаются нечётные знаменатели: стартуем с 1 и каждый раз делаем
шаг в два.

Все цифры, участвующие в вычислениях, — 500 членов, шаг знаменателя 2 и
множитель 4 — вынесены в именованные константы TERMS, STEP и FACTOR:
требование лабы запрещает «голые» числа там, где они считаются, а не
присваиваются напрямую.

После цикла в sum лежит частичная сумма, которая по формуле равна П/4 —
умножаем на 4 и печатаем. Все переменные здесь **double**: и слагаемые
дробные, и произведение быстро вырастает по точности.

Кстати, обратите внимание на результат: 3.139593. Два знака после запятой
верные — 3.14, а дальше ряд ещё не доехал. Формула Грегори славится тем,
что сходится до обидного медленно: точность растёт примерно на один знак
на каждые десять раз больше слагаемых. Это не баг программы, а честная
цена этого ряда.

## Задача 3

**Даны целые положительные числа A и B. Найти их наибольший общий делитель
(НОД), используя алгоритм Евклида.**

### Решение

```c
#include <stdio.h>

//Задача 3. Вариант 5
//Даны целые положительные числа A и B. Найти их наибольший общий
//делитель (НОД), используя алгоритм Евклида.

int main(void) {
    unsigned int a, b, c;
    int ta, tb; //ввод читается в знаковые: %u принял бы -3 за 4294967293
    int d;      //символ для вычерпывания буфера ввода
    int ok = 0;

    while (!ok) {
        printf("Введите числа a и b: ");

        ok = (scanf("%d %d", &ta, &tb) == 2) && (ta > 0) && (tb > 0);

        if (!ok) {
            while ((d = getchar()) != '\n' && d != EOF); //вычерпать плохой ввод
            printf("Ошибка: нужны два положительных числа. Повторите ввод.\n");
        }
    }

    a = ta;
    b = tb;

    while (b != 0){
        c = a % b;
        a = b;
        b = c;
    }

    printf("НОД: %u\n", a);

    return 0;
}
```

НОД — наибольшее из чисел, на которые делятся и a, и b без остатка.
Перебирать все делители подряд можно, но скучно; Евклид в «Началах» ещё
за триста лет до нашей эры заметил вещество покороче: если d делит и a,
и b, то оно делит и остаток a % b — ведь остаток получается вычитанием
целого числа b из a. Значит,

```c
НОД(a, b) = НОД(b, a % b)
```

и пару можно заменять, пока остаток не станет нулём. Цикл читается прямо
по этой формуле:

```c
while (b != 0){
    c = a % b;
    a = b;
    b = c;
}
```

Временная **c** обязательна: остаток надо спрятать до того, как b перезапишет
a, иначе он потеряется. Прогоним на 48 и 36: (48, 36) → (36, 12) → (12, 0).
b обнулился — в a остался ответ: 12.

Проверка ввода работает на логическом **&&** и цикле **while** со флагом
**ok**: scanf должен прочитать ровно два числа, и оба строго положительные —
НОД нуля с числом формально равен самому числу, но по условию задачи такого
ввода не бывает. Провал любой проверки вычерпывает буфер и запрашивает ввод
заново, поэтому после цикла пара заведомо корректна. Читаются числа во
временные **знаковые** ta и tb со спецификатором **%d**: беззнаковый scanf
%u принял бы −3 за 4294967293, и проверка «больше нуля» пропустила бы
отрицательное число; корректные значения затем переписываются в a и b.
Тип **unsigned int** у рабочих переменных взят не для красоты:
отрицательных чисел в задаче нет, зато беззнаковый тип вдвое расширяет
потолок положительных.
